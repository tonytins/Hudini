# Fonts in the appearance

**Status:** approved and built 2026-11-25. **Date:** 2026-11-25.

A game's fonts are part of its look, like its art, but today they can only be named in Swift. This design lets a
game's [appearance](2026-11-25-appearance.md) name its font files, fill the theme's default and monospace fonts, and
give a shared style a font of its own.

## Why

- **Games keep their design values in documents, except fonts.** Amtrak Status names B612 Mono and Overpass in
  `InterfaceFont.swift`, an agreed exception to its rule that design values live in its documents. Simburbia and
  Distro Tycoon 2 make the same exception since moving to Hudini.
- **One font per theme isn't enough.** Amtrak Status's split-flap tiles use B612 Mono while every label around them
  uses Overpass. `InterfaceTheme` has one font and one monospace font, and a `<Style>` can only choose between them.
- **Games pick fonts to match a look.** The Sims Online uses Comic Sans, and Simburbia moved to Comic Neue to match.
  A designer should be able to change that without editing Swift.

## Goals

- An appearance names font files, and the game loads them, as it does images.
- The appearance can fill the theme's default and monospace fonts. A game can still pass them in `InterfaceTheme`.
- An appearance style can draw in a named font, and text in that style is measured in the font it's drawn in.
- Window documents stay plain UIScript: nothing new appears in them.
- Without fonts in the appearance, everything reads and draws exactly as it does now.

## Non-goals

- **Named fonts in window documents.** A window's `font` keeps the spec's two values, `interface` and `monospace`. A
  window that wants a named font uses a shared style that has one.
- **A change to the UIScript spec.** Fonts stay a Hudini host feature.
- **Glyphs beyond ASCII.** raylib loads printable ASCII by default, and no game needs more yet. A `codepoints`
  attribute can come later, which older readers skip.
- **Loading fonts in Hudini.** The game loads and unloads them, as it does textures.
- **Other theme values in the file,** such as colors and corners. They get their own design when a game asks.

## How it works

### The file

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Appearance version="1">
  <Font name="text" path="fonts/Overpass-Regular.ttf" size="48"/>
  <Font name="tiles" path="fonts/B612Mono-Bold.ttf" size="48"/>
  <Fonts default="text" monospace="tiles"/>

  <Style name="tile" font="tiles" fontSize="title" textColor="#F2F2F2"/>
</Appearance>
```

Two elements join the appearance, and both exist only there. A window can't hold either.

**`<Font>`** names a font file.

| Attribute | Value |
| --- | --- |
| `name` | Required. Unique among fonts, and neither `interface` nor `monospace`, which a style's `font` already means. |
| `path` | Required. Where the file is, which the game's `loadFont` interprets, as `loadImage` does an image's `path`. |
| `size` | Required, above 0. The pixel size the glyphs are made at when loaded. Text draws at its style's or role's size, scaled from this one, so a size near the largest text keeps it sharp. |

**`<Fonts>`** fills the theme's two fonts, at most one per appearance, like `<ScrollBar>`. Both attributes are
optional, and each names a `<Font>`.

| Attribute | Value |
| --- | --- |
| `default` | The font text uses without a `font` in its style, or with `font="interface"`. It replaces `InterfaceTheme.font`. |
| `monospace` | The font a style with `font="monospace"` uses. It replaces `InterfaceTheme.monospaceFont`. |

The attribute is `default` rather than the spec's `interface`, because next to `monospace`, `interface` reads as if
monospace text weren't part of the interface. A `<Style>` still writes `font="interface"`, as the spec says.

### Styles with a named font

In an appearance, a `<Style>`'s `font` takes `interface`, `monospace`, or the name of one of its `<Font>`s. In a
window, it takes `interface` or `monospace`, as it does now.

- A window uses a styled font through a shared style: `style="tile"`. The style comes into the window with the font it
  names, as shared images do.
- **A window that overrides the style by name overrides it whole,** as with any style. A window's own `tile` style
  can't name `tiles`, so it draws in the default font, or in monospace if it says so.
- `UIScript.Style` gains `fontName`, the named font, alongside the `font` typeface it has now. A style has one or the
  other.

### Loading

The game gives the view a `loadFont` closure, as it gives `loadImage`:

```swift
let appearance = try Appearance(contentsOf: appearanceURL)
let theme = InterfaceTheme.standard.withFonts(from: appearance, loadFont: fonts.load)
let chat = try UIScript(contentsOf: chatURL, appearance: appearance)
let view = UIView(script: chat, theme: theme, loadImage: textures.load, loadFont: fonts.load)
```

- **`loadFont`** receives each `<Font>` and returns a raylib `Font`, or `nil` when it can't load one. It runs after
  `InitWindow`. The game owns the fonts: it caches them so each file loads once, keeps them loaded while views use
  them, and unloads them before `CloseWindow`. Mipmaps and texture filtering are the game's to choose, as Amtrak
  Status's trilinear filtering is now.
- **`InterfaceTheme.withFonts(from:loadFont:)`** returns a copy of the theme with the appearance's `<Fonts>` in place
  of its own. The appearance wins when both name a font: the file is the designer's choice, and the theme is the
  fallback. A slot the appearance leaves out, or whose font didn't load, keeps the theme's. The game passes the
  resulting theme everywhere, including to `WindowFrame`, `ButtonRow`, and `NoticePanel`, which draw outside any
  view. When it changes theme, such as for dark mode, it calls `withFonts` on the new one.
- **`UIView`** loads the named fonts its styles use through `loadFont`, once, during creation, as it loads images. A
  font that doesn't load is listed in `missingFonts`, like `missingImages`, and text in its style draws in the
  default font.

### Measuring

A control whose style names a font draws with a copy of the view's theme with that font, the way a `monospace`
control draws with `theme.monospaced` now. Lists, text areas, and fields measure through their theme, so wrapping,
scrolling, carets, and clicks use the same font the text is drawn in.

### What other readers see

- **Window documents are unchanged,** so VentureOS reads them as it does now. Only appearance styles can name a font.
- **Depot** draws through `depot-render --appearance`, which gains font loading so documents draw with the game's
  fonts.
- **An older Hudini** refuses an appearance with `<Font>` or `<Fonts>`, naming the element, since an unknown element
  refuses the file. A game moves to a Hudini that has fonts, then adds them.

### Errors

`Appearance` throws `UIScriptError` with line numbers for: a `<Font>` without a `name`, `path`, or `size`; a `size`
that isn't above 0; a duplicate font name; a font named `interface` or `monospace`; a second `<Fonts>`; and a
`<Fonts>` or `<Style>` naming a font that isn't there. A window style whose `font` is anything other than `interface`
or `monospace` is refused, as now.

## Compatibility

The appearance stays at `version="1"`. Adding elements to it is a new feature an older Hudini refuses by name, which
is the boundary the appearance design chose: "one it can't [skip] is an element or a new version". No appearance in
use today has fonts, so nothing that reads now stops reading.

Nothing changes for a game whose appearance has no fonts, or that has no appearance. Breaking changes for games:

- **Amtrak Status, Simburbia, and Distro Tycoon 2** need no changes to keep working. Adopting fonts means moving
  their font files' names into `appearance.xml` and their loading into a `loadFont` closure, then deleting their
  Swift font lists. Text widths change only if a game loads at a different `size` than it does now.

## Phases

1. **Design note:** this document.
2. **Scaffolding:** read and validate `<Font>`, `<Fonts>`, and named fonts in appearance styles, with tests. Nothing
   draws with them yet.
3. **Resolution:** shared styles bring their fonts into windows, `UIView` takes `loadFont` and reports
   `missingFonts`, controls draw and measure in their style's font, and `InterfaceTheme.withFonts(from:loadFont:)`
   fills the slots. Headless tests for resolution; a runtime check for drawing and measuring.
4. **Demo:** the demo's appearance gets Comic Neue from Google Fonts, with its Open Font License beside it, so the
   Sims windows draw in their game's look.
5. **Docs and Depot:** `UISCRIPT.md`, the README, and the roadmap; `depot-render` loads fonts.

## Calls made in writing it

The owner decided: fonts live in the appearance, not window documents; a window reaches a named font only through a
shared style; the appearance fills both theme slots, and games can still pass them in `InterfaceTheme`; the slot
attribute is `default`, not `interface`; no glyphs beyond ASCII yet; and Comic Neue for the demo. The spec's `font="interface"` stays, and
VentureOS is handled separately.

These were the writer's calls:

- The appearance's fonts win over the theme's when both name one.
- `<Fonts default monospace>` is its own element, so `<Font>` keeps the same shape as `<Image>`.
- `size` is required, since there's no size that suits every font and game.
- `path` is the only way to find a font. `<Image>` has `assetID` for TSO's art, but no game finds fonts by ID.
- The slots reach the theme through `withFonts`, which the game calls, rather than through `UIView`, so components that
  draw outside a view get the same fonts.
- A font that doesn't load falls back to the default font and is listed in `missingFonts`, rather than refusing the
  view, as images do.
- Hudini has no font loader of its own. Every game writes a short `loadFont`; if they turn out the same, a shared one
  can follow.
